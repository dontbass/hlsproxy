# HLS Proxy (анти-фриз) для OpenWrt

Кэширующий HLS-прокси с отложенным эфиром. Работает на роутере (aarch64), принимает
плейлист провайдера (список каналов m3u, master или media m3u8) и отдаёт плееру
(OTT Navigator и т.п.) эфир с отставанием. За счёт этого отставания провалы скорости
и зависания провайдера гасятся.

```sh
wget -qO- https://raw.githubusercontent.com/dontbass/hlsproxy/main/install.sh | sh
```

Где найти: LuCI → Службы → HLS Proxy (генератор ссылки, настройки, состояние каналов).
Ссылка для плеера: `http://<роутер>:8888/playlist?url=<urlencoded ссылка провайдера>`.

## Как работает

- На каждый канал работает свой воркер. Он сам опрашивает плейлист провайдера и качает
  сегменты в `/tmp/hls_cache` (RAM) **по порядку**, по умолчанию в 2 потока.
- Плееру отдаётся плейлист, край которого отстаёт от эфира на `delay` секунд.
  Край двигается **строго по часам** и **только по полностью скачанным сегментам**.
  Плеер никогда не получает ссылку на сегмент, которого ещё нет.
- Загрузка без общего таймаута. Если 12 с не пришло ни байта, загрузка обрывается,
  затем **докачивается через Range**. Длина сверяется с Content-Length. HTML/JSON вместо
  видео отбрасывается. Битый или недокачанный сегмент в кэш не попадает.
- Если провал провайдера длиннее запаса, край ждёт, а после восстановления догоняет
  расписание пачкой (до `max-burst` сегментов) и возвращает плееру буфер.
- Если сегмент потерян (8 попыток), он пропускается с `#EXT-X-DISCONTINUITY`, поток не встаёт.
- Из master-плейлиста остаётся только лучшее качество: смена качества означает холодный
  старт и фриз.
- Канал без зрителей 60 с останавливается, кэш чистится.

## Настройки (`/etc/config/hlsproxy` или LuCI)

| опция | по умолч. | смысл |
|---|---|---|
| delay | 60 | отставание от эфира, сек. Фактически не больше окна плейлиста провайдера |
| start_segs | 3 | сегментов на старте (собственный буфер плеера) |
| window | 8 | сегментов в плейлисте плеера |
| concurrency | 2 | параллельных загрузок на канал |
| all_variants | 0 | 1 = не выкидывать качества из master |
| ua | | User-Agent к провайдеру (пусто = как у плеера) |

## Диагностика

`http://<роутер>:8888/status` (то же самое в LuCI):

- `delay_s`: фактическое отставание от провайдера;
- `ready_ahead_s`: готовый запас в RAM впереди плеера;
- `realtime_x`: во сколько раз быстрее реального времени качаются сегменты (< 1.2 — плохо);
- `stalls`: сколько раз запас исчерпывался (провал был длиннее запаса).

Если на ТВ фризы, а `stalls = 0`, проблема не в доставке. Возможные причины: сам поток
провайдера, Wi-Fi до ТВ, декодер.

Логи: `logread -e hlsproxy -f`.

## Сборка

```sh
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o bin/hlsproxy_aarch64 .
SIM=1 SIM_WINDOW=15 SIM_DELAY=10 SIM_MAX_STALLS=0 go test -run TestSim -v   # симуляция нестабильного провайдера
```
